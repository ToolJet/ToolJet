# ToolJet Database page (frontend)

The workspace's built-in database UI at `/:workspaceId/database`: a tables panel on the left, a strip of open-table tabs on top, the grid for the active table below. Backend is `server/src/modules/tooljet-db/`.

## Domain terms

- **Open table** — `selectedTable` in context (`{}` when none). It is also the **active tab**.
- **Open tabs** — `openTabIds`, ordered table ids. Labels come from `tables`, never a copy of the name.
- **Environment** — `tjdbStore.selectedEnvironment`, mirrored in `?env=`; the grid shows it and schema edits write to development; row writes (add, cell edit, edit row, delete) go to the selected environment.

## Invariants & gotchas

- Open a table only through `openTable(table)` (context). Never call `setSelectedTable` to switch tables: the tab list would not follow.
- Tabs persist per browser and workspace in `localStorage` key `tjdb-open-tabs:<workspaceId>` as `{ids, activeId}`. Saved state is untrusted: `parseStoredTabs` falls back to "nothing open", `reconcileTabs` drops ids of deleted tables.
- Restore order on first load: saved tabs, then `?table=<id>` (opened on top), then the App Builder handoff (`localStorage.tableDetails`). Nothing is written (storage or URL) before that first restore.
- No table is opened by default. First visit, or "Close all tabs", shows the empty state.
- Rows are server state in react-query, never component state. Nothing fetches rows by hand: change the view in the store and the query follows; after a write call `handleRefetchQuery()` (context; an invalidate, any arguments are ignored). A cell save writes the cache with `patchCachedRow`, scoped to one table in one environment (another table can share a primary key).
- `setQueryFilters`, `setSortFilters` and `setPageSize` return to page 1 in the store. Callers never reset the page themselves.
- Each open table keeps its own view in `views[tableId]` (`{queryFilters, sortFilters, pageCount, pageSize, scrollTop}`); a table with no entry shows `DEFAULT_VIEW`. Components read the open table's view through `selectView(state)` (select one field, never the object) and write it through the store actions, which write `views[viewTableId]` (and do nothing with no table open). Never set `queryFilters` and friends on the store root: they no longer exist there.
- Switching tabs only moves the pointer: `openTableView(tableId)` sets `viewTableId` (from the `[selectedTable]` effect in `Table/index.jsx`), so a table comes back as it was left. Rows wait until `viewTableId` matches the open table, so a new table is never read with the previous table's view. A switch of environment drops every view (`switchEnvironment`, which also resets page size and scroll). Closing a tab, "Close others", "Close all" and deleting a table drop the views of tables no longer in `openTabIds` (`pruneViews`, an effect in `useOpenTabs`). Views are in memory only: a reload starts every table on its defaults. The environment is in the URL (`?env=<id>`); see the next point.
- A saved filter or sort can name a column that a schema edit removed or renamed, and "Edit table" works on any table in the panel, open or not. So `resetView(tableId)` (drops `views[tableId]`; the open table falls back to `DEFAULT_VIEW`) runs after a saved Edit table (`handleEdited` in `TableActionsHost`), a column drop (`useColumnActions`) and a column rename (`EditColumnForm`). Only another session or tab can still leave a stale filter: the rows query then fails with the server's error until the filter is cleared.
- `ClosableTabs` fills the room its parent gives; keep sibling strip items `shrink-0` or it will not scroll.
- Preflight is off: a solid border style alone gives the other sides 3px. Use `tw-border-0` plus the one side.
- The tables quota (`tablesLimitReached`) is read once in `index.jsx` and shared through context; never call `useTablesLimit` from a component. It refetches on a change of table *count* only (a new `tables` array is made on every tab switch).
- Specs that build the context by hand must use `useOpenTabs` (the context defaults are no-ops). Specs that import the real store go in `__tests__/integration/`.
- Cypress `data-cy`: `create-new-table-header`, `edit-table-header`, `save-changes-button`, `table-name-label`, `table-name-input-field`, `add-columns-header`, `add-more-columns-button`, `schema-table`, `schema-row-<name>`, `column-name-input-field`, `type-dropdown-field`, `column-default-input-field`, `default-value-input-field` (column drawers), `column-name-input-field-label`, `data-type-dropdown-section`, `data-type-locked-reason`, `data-type-omitted-footer`, `timezone-type-dropdown-section`, `cast-report-<state>`, `create-new-column-header`, `unique-checkbox`, `default-input-field`, `not-null-checkbox` / `null-checkbox`, `add-relation-button`, `relation-form`, `relation-card-<column>`, `table-tab-strip`, `<table>-tab` (+ `-close`), `open-or-create-table-button`, `open-tabs-menu-button`, `no-table-open`, `expand-tables-panel`, `data-toolbar`, `data-toolbar-table-name`, `filter-chips`, `filter-chip-<key>`, `more-filters`, `clear-all-filters`, `migration-history-button`, `add-new-data-button`, `filter-button`, `sort-button`, `filter-section`, `filter-add-button`, `filter-clear-all-button`, `filter-cancel-button`, `filter-apply-button`, `filter-row-<key>` (same for `sort-`), `select-column-field`, `select-operation-field`, `select-order-field`, `value-input-field`, `delete-icon`, `selection-bar`, `delete-row-records-button`, `edit-row-button`, `add-row-button`, `inline-add-row`, `save-new-row-button`, `cancel-new-row-button`, `add-column-button`, `column-menu-icon`, `edit-column-option`, `delete-column-option`, `table-footer-section`, `total-records-section`, `records-dropdown-field`, `previous-page-button`, `next-page-button`, `page-<n>-button`.

- Footer: the grid's height is `100vh - 144px - --tjdb-above-table` (navbar 48 + toolbar 48 + footer 48); change the footer's height and that calc together. Empty is decided by `totalRecords === 0` ("Showing 0 records"); while the first load of a table runs (`total` 0, loading) the bar is empty, since a refetch keeps the previous page's rows (`placeholderData`) but never another table's. Loading (`rowsLoading || rowsRefetching`) disables the size select and Previous/Next. Preflight is off: the Pagination `ul` needs `tw-m-0 tw-p-0` or the bar grows past 48px.
- The toolbar has no record count, "n selected" text or Delete rows button: selection lives in the bulk bar over the grid. `Table/Grid` selects, edits one row in a drawer and bulk-deletes rows, moves a focused cell with the keyboard, edits cells in place, adds a row inline and edits or deletes a column from its header menu. The toolbar's "Add new row" still opens `CreateRowDrawer` (the full form: defaults, JSON, foreign key lookups); the grid's "Add row" footer opens the inline row.
- Create table drawer (`Drawers/CreateTableDrawer`): the draft lives in `useTableDraft` and the form remounts per opening. The `id` serial primary key is pinned (first, not draggable, not removable) while it is the only primary key. A new type resets the default, not null and unique; a primary key survives a type that allows it and is dropped otherwise (boolean, timestamp, jsonb). A relation is dropped when its column is removed or becomes boolean, serial or jsonb, and follows a rename. Relations are added inline (`RelationFormCard`), not through the old `ForeignKeyTableForm` sub-drawer, which is deleted along with the other legacy table and column forms. A column that has a relation takes its default from a `ForeignKeyValueCombobox` of referenced values (`RelationDefaultPicker`; NULL is the first choice). The timestamp time zone has no control yet (the picker uses the column's `configurations.timezone`, else the browser's); product has not designed it. `createTable` / `editTable` are unsaved sources.
- Edit table drawer (`Drawers/EditTableDrawer`): same parts as Create, over `TableSchemaScope`. Stored columns carry `existing: true`: their type is locked (a cast depends on the rows; change it from the column's edit option), new columns pick one. No reorder. Save sends the `edit_table` diff (`toEditPayload`: old and new for a kept column, old only for a removed one, new only for an added one) through the migration confirmation, with a banner when the primary key changes. Foreign keys are not part of Save: add, edit and remove each run their own migration at once (`useLiveRelations`), against the saved table name, then the draft's relations are reloaded. Only stored columns are offered as a relation source. The loading state renders the real header and footer: the drawer's focus trap crashes on a first render with nothing focusable.
- Unsaved changes guard: a source reports `dirty` with `useReportUnsaved(id, dirty)` (cleared on unmount, which is what a discard does). Dirty means: `inlineAddRow` the draft is saving or has a value in `draft.values`; `cellEditor` the draft differs from the cell value; `editRow` the loaded values differ (typing back clears it); `editColumn` name, default, type, not-null, unique or time zone differs (the relation saves itself, so it never makes the drawer dirty); `createColumn` any field is set; `createRow` any field was touched (not a comparison: a timestamp default is the time the form opened), reset by "Create & add another". `UnsavedChangesGuard` adds a `beforeunload` handler while anything is dirty. Asked about, through `runUnlessDirty` / `confirmDiscard` (clean path stays synchronous): switching the open table or closing the open tab (`openTable`, `closeTab`, `closeAllTabs` in `useOpenTabs`, so the strip, both pickers, the open-tabs menu and the tables panel are covered; opening the open table, closing another tab and "Close other tabs" never ask), switching environment (`HeaderEnvironment` select), and closing a drawer by backdrop, Cancel or Escape (scoped to that drawer's source id; a save closes through its own callback, unasked; `EditColumnForm` takes `onCancel` for Cancel because its `onClose` also runs after a save). Not asked: `applyTables` (restore, deleted-table reconcile), the migration history drawer's post-migration `switchEnvironment`, the missing-table fallback to development, deleting a table (own confirm), the cell editor's own Escape/Cancel/scroll. A dirty cell editor ignores an outside press (the press may start a switch that asks); Escape and Cancel still close it. Route changes out of the page (header links, back button) are not blocked: the app uses `BrowserRouter`, which has no `useBlocker`. New source: add it to `UNSAVED_SOURCES`, call `useReportUnsaved`, and give its drawer `useGuardedClose`.
- Inline add row: `inlineDraftReducer` (`idle`, `drafting`, `saving`) lives in `InlineAddRows`, which renders a sticky footer ("Add row") that turns into one tinted row of fields with ✓ (Save row) and ✕ (Cancel) icon buttons at its end; there is no footer under it. An untouched cell has no entry in `values` and is left out of the request, so the database default (or NULL) applies. `unsetLabel` says which: Auto for a serial column, the default value's text for a column with a default (JSON for jsonb), else Required (NOT NULL or primary key) or NULL. A cleared cell goes back to untouched, so the inline row cannot send an empty string, or an explicit NULL over a default (use the drawer). A serial column is never sent. A boolean is a select (untouched, true, false); every other type, foreign keys included, is a text input and the server casts it. Enter or ✓ sends it through `createRow` to the selected environment; ok refetches (`handleRefetchQuery`, the new row lands where the sort puts it) and opens a fresh draft; a refusal returns to drafting with the values kept, `mapRowError` puts unique, not-null and type errors on the cell the server names (the second dot-separated part of its message, as `RowForm` reads it) and anything else on the row (an alert above its buttons) and a toast. Each transition names its start state, so a result that arrives after Cancel cannot revive the draft. Esc or ✕ closes it (not while saving). The draft is dropped when the environment changes and survives a page, sort or filter change, so `Table/index.jsx` keeps the grid's add row mounted when a filter matches nothing or a delete empties the page (`canAddRows` is off only for a table with no rows, no applied filter and `totalRecords` of 0). No row-limit pre-check exists: a plan limit is the server's refusal, shown as a row error (the create row drawer shows the same message as a toast; the 451 upgrade modal belongs to the legacy `fetch` path, not `HttpClient`).
- Column menu: a Rocket `DropdownMenu` in each data column header (not the checkbox column), shown with `canEditSchema`. Edit opens `EditColumnForm` in a drawer; Delete goes through `useMigrationModal` (the confirmation that records the drop in the table's history, with the dependents warning), then reloads the columns and rows. Delete is off for a primary key column.
- Row drawers (`Drawers/RowDrawer/`, Figma Create/Edit row, 480 wide on `DrawerShell`): each column is a `RowField` with a Null | Default | Custom toggle (Default only when the column has a default; Null disabled for a NOT NULL column or a key) over a control for its type (text input, boolean switch, timestamp picker, JSON editor, foreign key picker). A column on NULL or Default shows a disabled field; clicking it returns to Custom. State per column is `{ mode, value }` (`rowRules.ts`, pure): create leaves Default columns and serial columns out of the request (the database applies them) and sends `null` for Null; edit sends only the changed columns, never a key, filtered by `buildRowFilter` over every key column, and refuses without every key value (a key of 0 is a value). A number, JSON document or cleared time left empty on Custom blocks submit, as does invalid JSON. Server refusals go through `mapRowError` onto the field. Enter creates and closes; Shift + Enter (`DrawerShell` `onSubmitAndStay`) creates, resets the fields, refocuses the first and counts "N rows added" in the footer until the drawer closes. Creating clears sort and filters, refetches and scrolls the grid to the top. Edit is blocked like delete (`getEditBlockedReason`): no key, a bigint or jsonb key, a key past 2^53. `EditRowDrawer` hands the form the row with a key for every column, as one stable object, and remounts it per opening. The same drawer opens from the id cell's expand button (`cells/ExpandRowButton`, on the first pinned key column: shown on row hover or while that cell is focused, off with the `getEditBlockedReason` text, absent without permission to select rows). Row hover washes the data cells and the empty space after the last column, not the checkbox, id or add-column cells (`HOVER_OVERLAY` in `GridRow`); a NULL follows its column's alignment, so it is right-aligned in a numeric column (Figma only shows the left-aligned text case; product to confirm); a focused cell shows the full value of a cut-off text in its tooltip. The JSON editor's look still comes from `Forms/styles.scss` (imported by `RowField`).
- Row selection invariants: TanStack `rowSelection` is controlled by `useRowSelection`, keyed by row id (the joined primary key values) and scoped to the page on screen. It is stored with `useRowsViewKey` (environment id, `viewTableId`, rows query string) and dropped during render when that key changes, so a page, page size, filter, sort, table or environment change clears it with no effect in any caller. Returning to an earlier page does not restore it. A delete clears it explicitly (a refetch keeps the key). A refetch with the same key keeps it. No cross-page selection. Checkboxes are enabled only with `canSelectRows` (`canEditTjdb`). `GridRow` is memoised: it takes `isSelected` and `canSelect` as props, because the row object outlives a selection change. The selected background is a translucent token laid over the opaque cell colour, so pinned cells stay solid.
- Cell navigation: the focused cell is `{rowIndex, columnId, editing}` from `cellNavigationReducer`, stored by `useCellNavigation` with `useRowsViewKey` and dropped during render when the key changes (like a selection). A refetch keeps it, so after a delete it can point past the last row: it reads as no focus until valid. An open editor is the exception: it follows its row (see Cell editing). `TableGrid` owns it; `GridRow` gets only `focusedColumnId` (null outside the focused row) and `isEditing`, plus stable callbacks, so a move re-renders two rows. Keys are handled on the `role="grid"` element (`tabIndex=0`, never `document`: a document listener would take the arrows from the filter popovers and drawers) and only when the event target is the grid itself: a checkbox, header button or the open editor handle their own, and the editor's portalled popover still bubbles through the React tree. The select column is never navigable. Arrows clamp; Tab and Shift+Tab move right and left, and at the first or last cell the reducer returns the same state so Tab is not prevented and leaves the grid. `aria-activedescendant` points at the cell (`cellDomId`, by column position). Only keyboard moves scroll: rows by `virtualizer.scrollToIndex` (`scrollPaddingEnd` covers the sticky header and the add row footer, which sit outside the virtualizer's coordinates), columns by `scrollLeftToReveal` (pinned columns and the sticky add column cell cover the edges). A scroll of the grid closes the open editor, so nothing may scroll it when an editor opens: fields are focused with `preventScroll`.
- Cell editing: Enter or a double click edits the focused cell (`canEditCells`, which `Table/index.jsx` sets from `canEditTjdb`; navigation works without it). Not editable: primary key, serial, jsonb and timestamp columns (their editors are not built: jsonb would save as a JSON string, a timestamp is shown in the column's time zone but stored as ISO), every column of a table without a primary key or with a jsonb key (`hasEditableKey`), and any row whose key is an integer past 2^53 (`hasExactKeyValues`: its digits are already lost, so the filter could match another row). A PATCH without a filter rewrites every row and `postgrest-proxy.service.ts` has no guard against it; the old grid built no filter for a table without a key. A boolean has no editor: Enter or a double click flips it and saves (NULL becomes true), so a nullable boolean cannot be set to NULL from the grid. Other cells show an input in the cell and a popover anchored 2px below it (Set to null only when `is_not_null === false`, Cancel, Save); a foreign key column with a single-column key shows a searchable list of the referenced values instead (a column inside a composite key is edited as text). Enter and Save send the draft; Esc, Cancel, an outside press and a scroll close it unsaved; an unchanged draft closes without a request. The editor is bound to the row id (the joined key values), not to a position: `TableGrid` keeps `editingRowId`, a refetch under the same view key that moves rows keeps the editor, its draft and the focus ring on that row, `saveCell` resolves the row by id (a vanished row toasts and closes the editor, no request), and a row that disappears closes the editor. A save that resolves after the editor was closed, or another opened, only closes the editor it belongs to. A refused save toasts the error and keeps the editor open with the draft. The PATCH goes to the selected environment (the service reads it) filtered with `key=eq.value` per key column; a key value of `null` refuses to send. On success `patchCachedRow` writes the cell (numbers as numbers, as a refetch would return them) so the row keeps its place under a sort, and nothing refetches. The cell's own click and double click are off while its editor is open: the editor and its popover sit inside the cell in the React tree and every click would take the focus back from the field. Draft text is sent as typed: a number column receives a string and the server casts it; an empty string stays an empty string unless Set to null is on.
- Bulk delete: `deleteRowsByPrimaryKey` sends `<key>=in.(…)` for one key column and `or=(and(a.eq.1,b.eq.2),…)` for a composite key (whole tuples, never one column), double-quoting values PostgREST reserves. It refuses to send without every key value. Delete is off (with a `title` reason) for a table without a primary key or with a bigint or jsonb key column (`getDeleteBlockedReason`): a bigint loses precision past 2^53 once parsed, and a jsonb value has no filter text. The bar renders nothing without `canSelectRows`. The query goes without a leading `?`: `proxyUrl` adds it. It runs against the selected environment (the service reads it from the store) and the selection is cleared when that changes. The old grid filtered a composite key on its first column only.
- The grid gets raw rows. Row ids and the delete filter come from stored values, so nothing may format them first: display text comes from an optional `formatValue` on a column object (`GridColumn`), which `Table/index.jsx` sets on timestamp columns with the column's configured time zone and `CellContent` applies.
- Grid facts: one scroll element (`role="grid"`) for both axes, header sticky, pinned cells use `position: sticky` with the offset from TanStack. Preflight is off, so cell borders are `tw-border-0` plus one side. The refetch bar and 60% dimming show while `rowsRefetching` (context: `isFetching && !isLoading`). The virtualizer lives in `TableGrid`, which owns the scroll ref: created in a child it would miss the element on mount. Under jsdom it mounts no rows unless element sizes are mocked (see `Grid/__tests__/TableGrid.spec.tsx`). Column widths are keyed by column name and saved per workspace and table in `localStorage` (`tjdb-col-widths:<workspaceId>:<tableId>`, the same place and try/catch as the open tabs): read once when the grid mounts, written when a resize ends or a width is reset to the default, never on each mouse move. A save replaces the widths of the columns on screen and keeps the stored width of any other column (the table can have more columns in another environment); a width for a column that is gone everywhere is never looked up and stays in storage. `Table/index.jsx` keys the grid by table id, so each table mounts its own widths. Scroll: the grid takes `initialScrollTop` (applied once, in a layout effect, when its first rows render and the view is this table's (`viewTableId` matches, else cached rows of another view could clamp it); no report is made while the view is another table's) and reports `onScrollEnd(scrollTop)` 150ms after scrolling pauses, which `Table/index.jsx` writes to `views[tableId].scrollTop` by table id (a stable callback; `initialScrollTop` is read from the store with `getState`, not subscribed, so a report does not re-render the page). A pending report is dropped on unmount, so the last 150ms of scrolling before a tab switch is lost. Selection and the focused cell still reset with the view key.
- Filter chips come from `queryFilters`; removing one writes the store and the rows query follows. `Filter`'s effect only drops (with a toast) a NULL value used with a non-`is` operator; the query already skips it. The Filter and Sort triggers are Rocket icon buttons inside a tooltip `<span>`: `OverlayTrigger` must keep the button as its direct child to anchor its popover.
- Filter and Sort popovers edit a local draft; only Apply writes `queryFilters` / `sortFilters` (new objects: the store is frozen). A fresh row opens when nothing is applied; Apply ignores empty rows. Picking a sort column defaults the order to ascending. The operator list is still the raw PostgREST set from `_helpers/constants`.
- Preflight is off: `tw-divide-x` gives every cell a 3px top and bottom border. `ConditionRow` uses `[&>*+*]:tw-border-0 [&>*+*]:tw-border-l` instead.
- Rocket `PopoverTrigger` does not forward a ref, so a tooltip cannot wrap it directly: put the tooltip on a `<span>` around the trigger.
- `openMigrationHistory` has two callers, the toolbar's history button and the environment menu's "View migration history" row (`footerAction` of `useHeaderEnvironmentSelect`, only while a table is open); the drawer itself is mounted by `HeaderEnvironment`.

- Environment in the URL: `useEnvironmentUrl` (mounted in `index.jsx`) writes `?env=<id>` for any environment but development, same as the workspace constants page, replacing history and keeping other params (`table`). The id the page opened with is read once into a ref and passed to `loadEnvironments(urlEnvId)`: URL, then `sessionStorage`, then development, each only while licensed (a locked or unknown id falls through, and the effect then rewrites the URL to what was selected). Nothing is written before an environment is selected, or the opening value would be erased before it is read. The missing-table fallback to development goes through `switchEnvironment`, so it clears `env` too.
- Migration dialog: `useMigrationModal(options)` keeps its API. Title is required (Run is off while it is blank); `defaultTitle` is the change's own name and prefills it (`titlePlaceholder` is only a hint, as in History's New migration). There is no description field and no "Add migration" step: the SQL field is always open when `showSqlEditor` (the three delete actions have none), labelled "SQL (optional)" unless `sqlRequired`. The `{{self}}` / `{{table.<name>}}` table-reference hint is helper text under the SQL field (not the placeholder, so it stays while typing): users who write logical names get failures, because physical names are uuids. The dialog already sits above the drawers it opens from (Rocket's z-index beats the drawers' 1000-1002, checked in the browser), and every drawer that opens it needs `disableFocus` (Radix traps focus too). The compact SQL field has no search button (Ctrl+F still opens the panel).

- Sync dots: `migration_sync` comes only from the table list endpoint (`findAll`), so a thin `{ id, table_name }` (a rename sets one) has none and shows no dot; `useTables` merges the open table's thin shape over its row, so never write `migration_sync` into `selectedTable`. The list is read again when a migration is recorded (`migrationsVersion` bump, in `useTableMigrations`) and after a promote, which is what keeps the dots current; opening the page does not read it twice. The dot's hover target is a 24x32px box cancelled by negative margins (a 6px dot is too small to hit), so keep those margins with the size. The dot sits at the end of the row, before the hover menu, as in the Figma; the hover menu appears beside it and moves it left.
