# Shared version lifecycle

`VersionManagerDropdownContent` is the one dropdown implementation for App Builder, Modules, and Query Library. Its rows, Save/Create draft/Edit forms, and Promote/Release confirmations consume `VersionLifecycleContext`. Do not add a resource-specific copy of these components.

`VersionLifecycleProvider({ value, children })` supplies `{ resourceType, selectedVersionId, versions, environments, selectedEnvironment, releasedVersionId, loading, error, capabilities, notices, actions }`. `useVersionLifecycle()` requires a provider; it never falls back to app state.

Rows have `{ id, name, status: 'DRAFT'|'PUBLISHED', description, parentVersionId, createdFromVersion, currentEnvironmentId, createdAt }`. The app adapter also preserves existing Git metadata. Names and descriptions use `versionValidation.js`; punctuation such as dots, slashes, and plus signs remains valid. Save/Create draft validate trimmed names as before; Edit validates the original length.

Required promise actions: `selectVersion(id)`, `selectEnvironment(id)`, `refresh()`, `saveDraft(id,{name,description})`, `createDraft({name,fromVersionId})`, `editDraft(id,{name,description})`, `promote(id)`, `release(id)`, `deleteVersion(id)`. Adapters own stores, APIs, version switching, and errors; shared components own dialogs, local search, loading presentation, and user-facing errors.

Environment selection in the dropdown means **browse**: shared content retains a local filter. `selectedEnvironment` still identifies the editor's committed environment. The app adapter remembers the browsed environment in a ref; `selectVersion(id)` switches to that environment before switching the editor version. Opening resets browsing to the committed environment. App-only `actions.openDropdown()` performs that reset; other adapters use `refresh()` when opening and should reset their browse target there. `capabilities.visibleVersionIds` may limit displayed rows while `versions` retains all source/released rows. `capabilities.developmentVersionIds` limits Save/Create draft source rows. Without those ID sets all supplied rows are used.

Capabilities used by content: `readOnly`, `multiEnvironment`, `canPromote`, `canRelease`, optional `isSaving`, `isAiBuildingApp`, `devPinnedLibrariesCount`, and `environmentOptions`. Environment options are `{ environment, disabled, tooltipMessage, showTooltip, showEnterpriseIcon }`; adapters must supply access/licence restrictions. Existing app environment permission calculation is shared through `environmentOptions.js`, and the existing EE environment wrapper uses the same `EnvironmentSwitcherContent` markup.

`capabilities.git` and optional Git actions (`refreshFromGit`, `pullVersion`) belong only to the app adapter. Query Library leaves Git disabled/absent and supplies no app identity. `notices` may be a release-message array or `{ release, dependencyMessage }`; `dependencyMessage(name)` supplies the existing in-use warning's resource copy. App-only `loadReleaseNotices` fetches consumer pins, and `reportError` writes to the app debugger.

`useAppVersionLifecycle` contains app store/API/Git effects. `AppVersionLifecycleProvider` and `withAppVersionLifecycle` support existing standalone callers. The wrapper checks for an existing provider in a separate component boundary, so explicit library providers never execute the app hook. EE form wrappers preserve this boundary. The public `VersionManagerDropdown({darkMode})` entry remains the app/module wrapper, including existing router environment-query updates.

Tests: `__tests__/integration/moduleLifecycle.spec.jsx` uses the real composed store through `AppBuilderTestSession` and MSW. `__tests__/versionLifecycle.provider.spec.jsx` exercises the same UI with explicit resource actions and asserts zero HTTP requests, including through edition wrappers. `__tests__/versionValidation.spec.js` pins the existing name rule and limits. Release consumer-pin notices remain covered by `../__tests__/ReleaseConfirmation.library.spec.jsx`.

Normalization authority: promotion updates the committed environment and fetched rows without rewriting `selectedVersion`. Use the fetched row's normalized `currentEnvironmentId` ahead of selected snapshot data. Do not reverse all metadata precedence: immediate draft edits update selected/development metadata while the dropdown row cache may still contain the old name. The integration suite covers both two-step promotion through Release and immediate draft metadata updates.

`DependencyWarningDialog({open,title,message,darkMode,onClose})` owns the existing Modules portal/icon/footer/acknowledgement markup. Shared version deletion uses it for module errors and only typed `LIBRARY_QUERY_IN_USE` errors for `query-library`; ordinary 409/released/sole-version errors remain errors. Whole-module and whole-library-query callers use the same component. Library API errors expose the server response code; blocked deletes retain selection.
