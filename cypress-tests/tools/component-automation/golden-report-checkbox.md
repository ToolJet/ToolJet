## Root-cause of the properties failures (actionable facet-coder refinements)
1. **`verifyAndModifyToggleFx` has a toggle side-effect.** Signature `(paramName, defaultValue, toggleModification=true, hiddenFx=true)`: it reveals fx, asserts the `.cm-line` text == defaultValue, clicks fx back, THEN (default) clicks the toggle — flipping the value. The coder called it twice for `mandatory`: the first call (toggleModification defaulted true) flipped it ON, so the second call's fx assertion saw `{{true}}` while expecting `{{false}}`. FIX: the coder must model the side-effect — use one call to verify+flip, assert the DOM effect, then call again with the flipped default (or pass `toggleModification:false` for a pure read). Encode this in the facet-coder rules with a validated toggle example.
2. **fx value format assumption.** The coder passed the config default verbatim (`{{false}}`); confirm what the `.cm-line` actually renders for a boolean toggle in fx mode and cache it. RESOLVE-LIVE this rather than assuming.
3. **`verifyAndModifyParameter('Custom validation', '{{false}}')`** — customRule is a code field; passing a boolean-ish literal is questionable; use a `fake.*` expression or RESOLVE-LIVE the customRule assertion.
